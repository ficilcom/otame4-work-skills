# 活動の進め方

## 時間の作り方

週に使える時間は、本人の生活から本人が決める。「週に何時間なら続けられるか」から始め、活動ごとの時間を見積もって合計が収まるかを見る。以下は架空の例であり、標準的な配分ではない。

| 活動 | 時間がかかる場面の例 | 平日日中の枠 |
| --- | --- | --- |
| 求人票・スカウトを読む | 条件の確認、質問の整理 | 不要なことが多い |
| 書類の作成・更新 | 職務経歴書の改稿、応募先ごとの調整 | 不要 |
| エージェント・紹介者との面談 | 初回面談、求人の紹介を受ける | 相手により平日日中のことがある |
| 面接・面談 | 移動を含む拘束、事前準備 | 対面は平日日中が多いが、企業によって違う |
| 見直し | 表の更新、続けるかの判断 | 不要 |

平日日中の枠は、有給・半休・時間単位の休暇の扱いを**本人の職場の就業規則や休暇の規程で確認**する。取得理由の申告が要るかも規程による。申告が要らない規程のもとで理由を言わないことは偽りではないが、申告が要る場合に別の理由を作る段取り、勤務時間中に現職の設備や回線で活動する段取りは作らない。申告が要る場合は、相手先に時間帯やオンラインでの実施を相談する、時間単位の休暇を使うなど、偽らずに枠を作る方法を本人と探す。オンラインでの実施や時間帯の相談は、相手先に本人が確認する。

## 経路の使い分け

特定のサービスを推薦しない。本人が使う経路について、誰に何が開示され、どこに取り決めがあるかを確認する。以下は経路の種類ごとの一般的な確認点であり、各サービスの実際の条件は規約や公式情報で確認する。

| 経路の種類 | 開示される相手と範囲 | 確認すること | 辞退・取り下げの相手 |
| --- | --- | --- | --- |
| 企業サイトからの直接応募 | 応募先の企業 | 応募後の個人情報の扱い、選考の連絡手段 | 応募先の企業 |
| 求人サイト | 応募した企業。プロフィールを公開する設定なら閲覧企業 | 公開範囲、現職や関連会社を閲覧不可にする設定の有無 | 応募先の企業（サイト経由の場合はその手順） |
| スカウトサイト | 登録内容を閲覧できる企業・エージェント | 公開範囲、現職を閲覧不可にする設定、経歴の匿名化の範囲 | スカウト元 |
| エージェント（人材紹介） | 担当者と、紹介先の企業 | 同一企業に他経路で応募しているときの扱い、推薦の同意手順、辞退の連絡先 | エージェント経由 |
| 知人・元同僚の紹介 | 紹介者と紹介先 | 紹介者に選考状況がどこまで伝わるか、辞退時の紹介者への配慮 | 紹介先と紹介者 |
| 公的な職業紹介 | 窓口と紹介先 | 利用条件、紹介状の扱い、窓口の受付時間 | 紹介先と窓口 |

同じ企業に複数の経路で進む場合、エージェントや紹介の取り決めに触れることがある。どちらの経路で続けるかを本人が決め、必要な連絡は本人が行う。スカウトの文面の仕分けは `scout-message-triage`、求人票の条件は `job-posting-analysis` の範囲。

## 現職への配慮

在職中の活動を現職に伝えるかどうかは本人が決める。伝えない場合に確認するのは次の範囲であり、隠すための手順を作るのではなく、意図せず伝わる経路を本人が閉じられるようにする。

- 公開プロフィールが現職・関連会社から閲覧できる設定になっていないか。
- 現職の端末、メール、回線、勤務時間を活動に使っていないか。
- 応募資料に現職や顧客の非公開情報が入っていないか（`career-inventory` の抽象化の考え方を使う）。
- 推薦者や紹介者に、選考状況をどこまで伝えてよいか。
- 就業規則の競業や兼業に関わる定めに、活動や入社時期が触れないか。定めの内容は書面で確認する。

## 応募の記録

企業、経路、段階、次の行動と予定日、相手が示した期限を1つの表にする。段階は本人の言葉でよいが、スクリプトでは `considering`（検討中）、`preparing`（書類準備）、`applied`（応募済み）、`interviewing`（選考中）、`offer`（内定・回答待ち）、`accepted`（承諾）、`not_selected`（不採用・見送り）、`withdrawn`（辞退・取り下げ）を使う。

経路が分からない応募は経路を空欄にしてよいが、その応募は同一企業の複数経路の検出に入らないので、分かり次第埋める。次の行動は、誰が・何を・いつまでにが分かる大きさにする。相手の期限（回答期限、提出期限）と自分で決めた予定日を分ける。辞退を決めた応募は、相手に伝えたかを記録し、連絡は本人が行う。内定が出たものは `offer-terms-check`、辞退の相手と段階は `offer-decline` の範囲。

## 見直しの区切り

見直す日を本人と決め、その日に「続ける」「減らす」「止める」「別の経路に変える」を選び直す。止める条件は本人が挙げた負担の兆候にする。架空の例: 「睡眠が削れる週が2週続いたら面接の予定を入れない」「現職の繁忙期は応募を増やさない」。

見直しの日に結論を迫らない。何も進んでいない期間があっても、それを失敗にしない。睡眠や体調の変化が続いていると話している場合は、活動をどうするかとは別に、医療機関や適切な相談先を使う選択肢を置く。病名や重症度は推測しない。活動をやめる、保留する、転職するか自体を考え直す（`job-change-decision`）も選択肢に残す。

## スクリプト入力

`scripts/plan_job_search.py` は材料が揃ったときの任意の補助。応募先の推薦や合否の見込みは出さない。以下は架空の入力例。

```json
{
  "as_of": "2026-09-18",
  "employed": true,
  "weekly_hours_available": 4,
  "weekday_daytime_available": false,
  "review_date": "2026-11-30",
  "stop_conditions": ["睡眠が削れる週が2週続く"],
  "activities": [
    {"label": "求人票を読む", "weekly_hours": 1},
    {"label": "職務経歴書の更新", "weekly_hours": 2},
    {"label": "面接", "weekly_hours": 1.5, "weekday_daytime": true}
  ],
  "channels": [
    {"id": "agent_a", "kind": "agent", "label": "エージェントA", "terms_confirmed": false},
    {"id": "scout_b", "kind": "scout_site", "label": "スカウトサイトB", "profile_public": true, "current_employer_blocked": "unknown"}
  ],
  "applications": [
    {"id": "a1", "employer": "架空商事", "channel": "agent_a", "stage": "applied", "next_action": "一次面接の候補日を返す", "next_action_by": "2026-09-25"},
    {"id": "a2", "employer": "架空商事", "channel": "scout_b", "stage": "considering"}
  ]
}
```

- `weekly_hours_available` と各 `weekly_hours` は本人の見積もり。未定なら省略し、`unknown` として扱われる。
- `weekday_daytime_available` は、在職中に平日日中の枠を作れると本人が確認したか。`activities[].weekday_daytime` は、その活動に平日日中の枠が要るか。
- `channels[].kind` は `direct` / `job_board` / `scout_site` / `agent` / `referral` / `public_service` / `other`。`profile_public` は経歴が閲覧される設定か、`current_employer_blocked` は `yes` / `no` / `unknown` / `not_applicable`。`terms_confirmed` は、エージェントや紹介の取り決めを本人が確認したか。
- `applications[].stage` は上の8段階。`next_action_by` は自分で決めた予定日、`reply_deadline` は相手が示した期限。`notified` は辞退を相手に伝えたか。
- `review_date` は見直す日、`stop_conditions` は本人が挙げた止める条件。

スキルのディレクトリを基準に実行する。引数を省略すると標準入力から読み取れる。利用者が保存を求めていない場合は、会話から必要最小限のJSONを標準入力で渡し、入力・出力ファイルを作らない。

```bash
python3 scripts/plan_job_search.py
```

保存を依頼されて作成した入力ファイルがある場合だけ、そのパスを引数に指定できる。

出力の `time` は時間の合計と余裕、`channels` は経路ごとの確認状況、`applications` は各応募の期限までの日数、`due` は次の行動と相手の期限を日付順に並べたもの、`flags` は確認の候補。`weekly_hours_exceeded` は活動を減らせという指示ではなく、どちらを変えるかは本人が決める。**どの企業に応募すべきか、何社に応募すべきかは出力に含まれない。**
