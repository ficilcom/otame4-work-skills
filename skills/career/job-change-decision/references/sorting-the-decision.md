# 判断材料の分け方

## 転職を既定にしない

このスキルの出発点は「どう転職するか」ではなく「**動くかどうか**」である。現職に留まる、現職の中で変える、転職する、その他の選択肢を、**同じ重さで並べる。** 相談されたという事実を、転職すべきという前提として扱わない。

同時に、留まることを勧めもしない。並べるところまでがこのスキルの範囲で、決めるのは利用者である。

## 不満を3つに分ける

不満をそのまま「転職の理由」にしない。次の3つに分けると、転職で変わる範囲が見える。

| 区分 | 見分け方 | 扱い |
| --- | --- | --- |
| 転職で解決しうる | 原因が今の会社・今の職務にあり、他社では違う | 転職の理由になる |
| **転職しても付いてくる** | 原因が働き方の癖、スキル、健康、家庭の状況にある | 転職では解決しない。移った先で同じことが起きる |
| 現職でまだ試していない | 原因が職務・人間関係・自分の状態にあり、働きかけをしていない | 試す余地が残っている |

**「付いてくる」かどうかは利用者が判断する。** こちらで「それは甘えだ」「それは環境の問題だ」と決めない。判断できない場合は `unknown` にして、そこが未確定であることを残す。

## 原因の所在

| cause | 何が原因か | 転職で変わるか |
| --- | --- | --- |
| `role` | 担当する職務、裁量、業務の内容 | 変わりうる。ただし職種が同じなら似た構造になることもある |
| `team` | 上長、同僚、チームの運営 | 変わりうる。ただし移った先の人は選べない |
| `company` | 制度、方針、評価、給与テーブル、事業の状況 | 変わりうる |
| `industry` | 業界の商習慣、単価、労働時間の構造 | **同じ業界に移るなら残る** |
| `self` | 自分の働き方、スキル、健康、生活の状況 | 移っても残ることが多い |
| `unknown` | 特定できていない | 変わる範囲が決まらない |

「なんとなく今の会社が合わない」は `unknown` である。**それらしい原因を割り当てない。** 原因が特定できないこと自体が、いま結論を出せない理由になる。

## 行き先と、失うもの

不満（現職から離れたい理由）だけでは判断できない。次の2つが揃って初めて比較になる。

- **行き先で得たいもの** — 次の職場で何を得たいか。得られなければ移る意味がないものはどれか。
- **いま持っていて失うもの** — 通勤時間、人間関係、慣れ、裁量、勤務時間の融通、育休・介護の実績。

**片側しか挙がっていない状態を、そのまま結論に進めない。** 不満だけが並んでいる状態は、比較の片側が空である、という事実として示す。「逃げの転職だ」といった評価をしない。

## 選択肢を並べる

転職と「何もしない」の2択にしない。

| 選択肢 | 現職を続けるか |
| --- | --- |
| 現職のまま、何も変えない | 続ける |
| 現職で改善を働きかける（担当、体制、働き方） | 続ける |
| 社内異動 | 続ける |
| 現職内での職種転換 | 続ける |
| 休職・療養 | 続ける |
| 副業（就業規則の定めを確認する） | 続ける |
| 先に学習や資格取得を行う | どちらもありうる |
| 転職 | 離れる |
| 独立・フリーランス | 離れる |

**すべてを検討しろという意味ではない。** 検討したうえで外したものは、外した理由とともに記録する。検討していないものが残っている状態と、検討して外した状態は違う。

体調に関わる不満がある場合、**休職・療養を選択肢から落とさない。** 転職活動そのものが負荷になることがある。医学的な判断はせず、選択肢として残すにとどめる。

## 期限と制約

判断には期限がつくことが多い。賞与の支給日、契約の更新、家族の事情、住宅ローン、在留資格。**これらは判断の材料であって、判断を迫る理由ではない。**

期限を決める場合は、**何が満たされたら決めるのか**を先に決める。期限だけを決めても、期限が来た日に材料が揃っていなければ決められない。

## スクリプト入力

`scripts/sort_decision_inputs.py` は材料を分けるだけで、結論も推奨も出さない。

```json
{
  "as_of": "2026-09-01",
  "concerns": [
    {
      "id": "c1",
      "text": "設計に関われず実装だけになっている",
      "cause": "role",
      "portable": "no",
      "tried_internally": "no",
      "severity": "high"
    }
  ],
  "wants": [{"text": "設計から関わりたい", "must": true}],
  "keeps": [{"text": "通勤15分", "importance": "high"}],
  "options": [
    {"code": "internal_transfer", "status": "ruled_out", "note": "異動の制度がない"},
    {"code": "job_change", "status": "considered"}
  ],
  "constraints": [{"text": "賞与の支給日", "date": "2026-12-10"}],
  "decision": {"deadline": "2026-11-30", "criteria_defined": false}
}
```

- `portable` は「転職しても付いてくるか」。**利用者自身の判断を入れる。** 判断できないなら `unknown`。
- `tried_internally` は `yes` / `no` / `not_possible`（試せる状況にない）/ `unknown`。
- `severity` は利用者の申告であり、優先順位の決定ではない。
- `options` の `status` は `considered`（検討した）/ `ruled_out`（検討して外した）/ `not_considered`。**検討して外したものは検討済みとして扱われる。**
- `decision.criteria_defined` は、何が満たされたら決めるかが決まっているか。

実行:

```bash
python3 scripts/sort_decision_inputs.py input.json
```

出力の `sorted_concerns` は不満の分類、`options` は選択肢の検討状況、`flags` は結論を出す前に埋めるべき点。**どの選択肢を取るべきかは出力に含まれない。**
