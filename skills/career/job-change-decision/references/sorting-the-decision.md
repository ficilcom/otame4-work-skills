# 判断材料の分け方

## 分類は仮置きとして使う

出来事、本人の受け止め、本人の予想、こちらの仮説、確認済みの条件を区別する。原因を一つに決められなければ `unknown` のままにする。分からないことがあっても相談は進められる。

| 見る観点 | 確かめること | 注意点 |
| --- | --- | --- |
| 別の職場で変わりうるか | どの仕事・体制・条件なら違いが出るか | 他社なら必ず改善するとは扱わない |
| 職場を変えても残りそうか | 何が残り、環境によって何が変わりうるか | 本人の予想であり、不変の性質ではない |
| 現職で変える余地があるか | 試した結果、試せる条件、試したくない理由 | 未実施は転職を止める理由にならない |

これらは排他的な3分類ではない。同じ悩みに複数の観点が当てはまる。不満の数から転職の効果を測らない。

補助スクリプトの `cause` は `role`（職務）、`team`（人間関係・体制）、`company`（会社の制度・方針）、`industry`（業界）、`self`（本人の働き方・生活の事情）、`unknown`（未確認）。本人が述べた仮の整理を記録する欄であり、`self` は本人の責任という意味ではない。業界や健康に関わる悩みでも、働く環境で変わる可能性を閉じない。

## 選択肢を段階に分ける

現職のまま過ごす、担当や体制の改善、社内異動、在職しながら仕事を調べる、転職活動、退職の判断などから、相談に必要なものを並べる。休養・休職、副業、学習、独立は状況に関係するときだけ扱う。全候補の検討を義務にしない。利用者が外したものを再び勧めるなら、新しく判断を変える材料が必要である。

「求人票を読む」と「応募する」、「転職活動をする」と「先に退職する」は負担・影響が違う。それぞれの段階で本人が選べるようにする。情報収集のための登録や経歴公開を自動的に含めない。

内定や引き留めを受けた後の相談では、「内定を受ける」「引き留めに応じて残る」「どちらも保留して確認を続ける」が選択肢になる。内定の条件の確認と比較、辞退の相手と段階は `offer` のスキルの範囲であり、ここでは応募したときに変えたかったことが各案でどう扱われるかを見る。

## 比較を変える前提

得たいことと守りたいことに照らして、各案の根拠と反証を置く。待遇や生活への影響、応募資格などの必要条件、仕事内容や人間関係への懸念を総合点に混ぜない。金額や制度が未確認なら、勝手に埋めずに確認手段を残す。

架空の例: 「担当を変えられるなら現職で設計経験を積めるが、変えられないなら社外の仕事内容を調べたい」という場合、担当変更の可否が比較を変える前提になる。実現できる場合とできない場合で次の行動を並べれば、原因をすべて確定しなくても進められる。

現職に留まることで続く負担も、動くことで失う可能性のあるものも扱う。現状維持を無負担としない。体調や安全への具体的な懸念があれば、先に負担を減らす方法を扱う。

## 期限の扱い

本人が挙げた契約更新などの期限と、こちらが提案する見直し時期を区別する。期限を理由に結論を迫らず、何を確認できれば選び直せるかを決める。確認できなかった場合も保留や別の確認方法を選べるようにする。

期限は判断期限（本人がいつまでに決めたいか）と、事情の期日（賞与の支給日、契約更新の通知期限、内定の回答期限、休業の予定など）に分ける。相手が定めた回答期限は、本人の判断を迫るものでも事情の期日として扱い、本人の判断期限と混ぜない。事情の期日は行動の順序を決める材料であり、それぞれの期日までに何を確かめられるか、期日を過ぎたら何が変わるかを本人と確認する。判断期限より前に来る期日は、順序を見落としやすいので先に並べる。

## 一次情報で確認する論点

相談の中で事実の確認が必要になりやすい論点。ここに事実は書かない。必要になったときに、本人の職場の書面か公的機関の公表資料を確認し、出典と時点を添える。確認できないものは未確認のまま残す。

| 論点 | 確認先の種類 | 記憶で埋めないこと |
| --- | --- | --- |
| 社内異動・社内公募・担当変更の制度 | 本人の職場の就業規則、人事制度の案内 | 制度の有無、応募条件、周囲に伝わる仕組み |
| 休職・休業の制度 | 就業規則、健康保険・公的制度の公表資料 | 取得条件、期間、収入の扱い |
| 賞与・退職金の支給条件 | 賃金規程、退職金規程 | 支給日、在籍要件、減額の条件 |
| 契約更新の通知時期と条件 | 雇用契約書、就業規則 | 通知の期限、更新の基準 |
| 退職の申出期限 | 就業規則、雇用契約書 | 申出から退職日までの期間 |
| 離職後の公的給付・保険・税 | 公的機関の公表資料 | 受給要件、手続きの期限、自己都合の扱い |
| 副業の可否 | 就業規則（`sidework-rules-check` の範囲） | 禁止・許可制・届出制の別 |

労働法・税務・社会保険の判断は専門家の確定判断として示さない。争いがある論点は、相談先の種類を示すにとどめる。

## スクリプト入力

`scripts/sort_decision_inputs.py` は材料が多いときの任意の補助。結論も推奨も出さない。対話にこのJSONを埋める義務はなく、不満のない相談では使わなくてよい。以下は架空の入力例。

```json
{
  "as_of": "2026-09-01",
  "concerns": [
    {
      "id": "c1",
      "text": "設計に関われず実装だけになっている",
      "cause": "role",
      "portable": "no",
      "tried_internally": "no",
      "severity": "high"
    }
  ],
  "wants": [{"text": "設計から関わりたい", "must": true}],
  "keeps": [{"text": "通勤15分", "importance": "high"}],
  "options": [
    {"code": "internal_transfer", "status": "ruled_out", "note": "異動の制度がない"},
    {"code": "explore_while_employed", "status": "considered"},
    {"code": "job_change", "status": "considered"}
  ],
  "constraints": [{"text": "賞与の支給日", "date": "2026-12-10"}],
  "decision": {"deadline": "2026-11-30", "criteria_defined": false}
}
```

- `portable` は「転職しても付いてくるか」。**利用者自身の判断を入れる。** 判断できないなら `unknown`。
- `tried_internally` は `yes` / `no` / `not_possible`（試せる状況にない）/ `unknown`。
- `severity` は利用者の申告であり、優先順位の決定ではない。
- `options` の `code` は `stay_as_is`、`stay_and_change`、`internal_transfer`、`role_change`、`leave_of_absence`、`explore_while_employed`（在職しながら情報を集める）、`upskilling`、`side_work`、`job_change`、`independent`。`status` は `considered`（検討した）/ `ruled_out`（検討して外した）/ `not_considered`。**検討して外したものは検討済みとして扱われる。**
- `constraints` は本人が挙げた事情の期日。`date` は任意で、未確認なら省略する。
- `decision.deadline` は本人の判断期限。`criteria_defined` は、何が満たされたら決めるかが決まっているか。

スキルのディレクトリを基準に実行する。引数を省略すると標準入力から読み取れる。利用者が保存を求めていない場合は、会話から必要最小限のJSONを標準入力で渡し、入力・出力ファイルを作らない。

```bash
python3 scripts/sort_decision_inputs.py
```

保存を依頼されて作成した入力ファイルがある場合だけ、そのパスを引数に指定できる。

出力の `sorted_concerns` は本人の申告の分類、`options` は既定の選択肢の検討状況、`constraints` は各期日までの日数（`days_until`）付きの事情、`flags` は確認の候補。未確認項目をすべて埋める必要はない。`changes_with_employer` も改善を検証した結果ではない。期日が判断期限より前にある事情は `constraints_before_deadline`、過ぎた期日は `constraints_passed`、日付のない事情は `constraints_undated` として出るが、いずれも順序と未確認の指摘であり、その期日に合わせて決めるべきという意味ではない。**どの選択肢を取るべきかは出力に含まれない。**
