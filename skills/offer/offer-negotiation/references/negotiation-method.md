# 交渉準備の進め方

## 前提

内定後の条件の依頼は、承諾の前に行うのが原則である。承諾した後に条件を変えるのは難しい。一方、承諾期限を過ぎてから依頼すると、依頼そのものが扱われないことがある。**期限と書面の状態を先に確定させる。**

このスキルが扱うのは、依頼の中身と根拠と段取りである。通るかどうか、どこまで上がるかは相手の事情で決まり、こちらからは分からない。見込みを書かない。

## 依頼項目の切り分け

依頼は「条件を良くしてほしい」ではなく、**何をどう変えてほしいか**の単位に分ける。

| category | 何を動かすか | 分け方の注意 |
| --- | --- | --- |
| `pay` | 基本給、固定手当、固定残業代、賞与、年俸 | 総額ではなく要素ごとに分ける。固定残業代を増やして総額を上げる案は、基本給を上げる案と別物である |
| `start_date` | 入社日 | 退職の申出期限と引き継ぎから逆算した日付にする。根拠は `resignation-plan` の結果を使う |
| `work_style` | 在宅勤務の頻度、勤務時間帯、時短 | 口頭の「相談可」は条件ではない。何日・何時間かで書く |
| `location` | 勤務地、転勤の範囲 | 変更の範囲の限定を求めるのか、初任地だけなのかを分ける |
| `title` | 職位、等級、役割 | 名称だけでなく、それに紐づく給与や評価の扱いも確かめる |
| `probation` | 試用期間の長さ、期間中の条件 | 期間中の給与・雇用形態が本採用後と違うかを先に確かめる |
| `other` | 上記以外（入社前の研修、機材、副業の可否など） | 依頼の文言を具体にする |

各項目に次の5つを置く。

- **現在の提示** — 書面の原文。要約しない。書面がなければ出典を添える。
- **希望** — 何をどう変えてほしいか。金額・日付・日数で書けるものは数値で書く。
- **優先度** — `must`（通らなければ承諾を考え直す）/ `want`（通ってほしい）/ `nice`（あれば嬉しい）。全部を `must` にすると、一部だけ通ったときに判断できない。
- **断られた場合** — `accept_anyway`（それでも承諾する）/ `decline_offer`（辞退する）/ `undecided`。**利用者が決める。** 決まっていない `must` は、依頼を出す前に決めておくことを勧める。依頼文で強く出た後に、断られて承諾すると次の依頼が通りにくくなる。
- **代わりの案** — 希望どおりでなくても受けられる案（等級見直しの時期を書面にする、入社日を2週間だけ遅らせる）。あれば添える。

## 根拠の種類

| kind | 何を指すか | 使い方 |
| --- | --- | --- |
| `written_offer` | 労働条件通知書、内定通知書の記載 | 提示内容の原文を示し、どこを変えてほしいかを特定する |
| `posting` | 求人票・募集要項の記載（提示範囲など） | 募集時の提示範囲と、提示額の位置を示す。求人票は契約の条件ではない |
| `interview` | 面接・面談での説明 | いつ誰が何と言ったかを利用者の記録と照らす。記憶だけなら断定しない |
| `own_record` | 現職の給与明細、源泉徴収票、実績の記録、資格の証明 | 事実のとおりに書く。現年収を実際より高く書かない |
| `public_source` | 公的統計、企業の公開資料（有価証券報告書の平均給与など） | 出典と時点を必ず付ける。職種・地域の区切りが応募先と合っているかを確かめる |
| `other_offer` | 他社の内定・選考の状況 | 伝えるかどうか、社名と金額を出すかを利用者が決める。存在しない提示を作らない |

**根拠がない依頼も出せる。** その場合は根拠のある依頼と混ぜず、「希望として」伝える形にする。根拠があるように見せる言い回しを作らない。

現年収を根拠にする場合、手取りではなく額面で、賞与と残業代を含むかを明記する。前職の給与を上回ることを求めるのは本人の希望であり、企業にそれを払う義務があるわけではない、という前提を崩さない書き方にする。

## 経路

| channel | 宛先 | 書き分け |
| --- | --- | --- |
| `direct` | 採用担当者、面接官 | 依頼の本文をそのまま企業に出す。感謝、入社の意向、依頼、根拠、回答期限への配慮の順 |
| `agent` | 転職エージェントの担当者 | エージェントに伝える本音（優先度、断られた場合の行動）と、企業に伝えてほしい内容を分ける。本音をどこまで伝えるかは利用者が決める |

エージェント経由の場合、エージェントが企業に何を伝えたかを後で確かめられるよう、伝えてほしい内容を文章で渡す。

## 依頼文で書かないこと

- 事実と違う現年収、実績、役職、他社の提示
- 利用者が決めていない「この条件なら必ず承諾します」
- 相手を急かす、または他社を理由に圧力をかける言い回し（利用者が他社の状況を伝えると決めた場合も、事実を伝えるにとどめる）
- 企業や面接官への評価、他の候補者との比較
- 承諾期限を一方的に延ばす前提（延長は依頼であって、決めるのは企業）

## 回答を受けた後

| 回答 | 次にすること |
| --- | --- |
| 全部または一部が通った | 改訂された書面を求め、`offer-terms-check` で確かめ直す。口頭の回答だけで承諾しない |
| 代わりの案が出た | 優先度と「断られた場合」に照らして、利用者が受けるかを決める |
| 通らなかった | 利用者が事前に決めた扱いに戻る。決めていなければ、ここで決める。こちらで結論を書かない |
| 回答が期限に間に合わない | 期限の延長を依頼するかを利用者が決める |

## スクリプト入力

`scripts/plan_negotiation.py` は、差額と日程と根拠の有無を並べるだけで、通るかどうかも、適正な金額も判定しない。

```json
{
  "employer": "架空システム株式会社",
  "as_of": "2026-09-08",
  "written_terms": true,
  "channel": "agent",
  "offer": {"acceptance_deadline": "2026-09-15"},
  "plan": {"request_date": "2026-09-09", "response_wait_days": 3},
  "requests": [
    {
      "id": "base",
      "topic": "月額基本給",
      "category": "pay",
      "priority": "must",
      "current_text": "基本給 月額280,000円",
      "ask_text": "基本給 月額310,000円",
      "current_amount": 280000,
      "ask_amount": 310000,
      "amount_unit": "monthly",
      "posted_range": {"min": 260000, "max": 340000, "unit": "monthly"},
      "if_declined": "accept_anyway",
      "fallback": "入社6か月後の等級見直しを書面に入れてもらう",
      "bases": [
        {"kind": "posting", "note": "求人票の月給26万〜34万円"},
        {"kind": "own_record", "note": "現職の基本給 月額300,000円（給与明細）"}
      ]
    },
    {
      "id": "start",
      "topic": "入社日",
      "category": "start_date",
      "priority": "want",
      "current_text": "2026年11月1日",
      "ask_text": "2026年12月1日",
      "current_date": "2026-11-01",
      "ask_date": "2026-12-01",
      "if_declined": "accept_anyway",
      "bases": [{"kind": "own_record", "note": "就業規則で退職の申出は1か月前まで"}]
    }
  ]
}
```

- `written_terms` は条件を書面（電子交付を含む）で受け取っているか。不明なら `null` にする。
- `channel` は `direct` / `agent` / `unknown`。
- `category` は上の表の値。`priority` は `must` / `want` / `nice`。省略すると `want` として数え、優先度が付いていないことを注記する。
- `if_declined` は `accept_anyway` / `decline_offer` / `undecided`。利用者が決めていなければ省略する。こちらで推測して入れない。
- 金額は `current_amount` と `ask_amount` を同じ単位（`amount_unit` が `monthly` か `annual`）で入れる。`posted_range` の単位が違う場合は比べない。
- 日付の依頼は `current_date` と `ask_date` を入れると、ずらす日数が出る。
- `bases[].kind` は上の表の値。`public_source` には `as_of`（資料の時点）を入れる。
- `plan.response_wait_days` は、依頼から回答までに見込む日数。分からなければ省略する。既定値で埋めない。

実行:

```bash
python3 scripts/plan_negotiation.py input.json
```

出力の `requests[].amount` は差額、年額換算、求人票の提示範囲での位置（`within` / `above_max` / `below_min` / `no_range` / `unit_mismatch`）。`schedule` は承諾期限と回答見込みの関係で、`answer_before_deadline` が `false` のときは回答が期限に間に合わない。`summary.pay_annual_difference_total` は金額の依頼がすべて通った場合の年額の差の合計で、見込みではない。
