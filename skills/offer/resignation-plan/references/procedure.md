# 退職と入社の段取り

## 順序

**内定を承諾してから退職を申し出る。** 逆にすると、内定が流れたときに戻る場所がなくなる。承諾の前に退職の意思を伝えない。労働条件が書面で確定しているかは `offer-terms-check` で確認する。

その上で、次の順に進む。

1. 就業規則の退職に関する定めを確認する（申出の期限、提出物、引き継ぎの扱い）
2. 直属の上長に口頭で申し出る
3. 退職届・退職願を提出する（会社の様式に従う）
4. 引き継ぎ計画を作り、実施する
5. 有給休暇の消化を申請する
6. 貸与品を返却し、書類を受け取る
7. 空白期間があれば、健康保険・年金・住民税の手続きをする

## 申出の期限

就業規則に申出の期限が定められていることが多い。**期限は会社ごとに違うため、必ず自社の就業規則を見る。** 民法の定めとの関係は、事案によって扱いが分かれる論点であり、ここで法的な結論を出さない。

期限に間に合わない日程になっている場合、選択肢は次のいずれかであり、どれを取るかは利用者が決める。

- 退職日を後ろにずらす
- 入社日の変更を転職先に相談する
- 会社と個別に調整する

**「規則を無視して退職できる」とも「絶対に無理だ」とも書かない。** 会社との調整が必要な状態である、という事実までを示す。

## 有給休暇

- 残日数を給与明細か勤怠システムで確認する。**記憶で計画を立てない。**
- 退職日までの平日数を超える日数は消化できない。引き継ぎと同時には消化できない点も含めて日程を引く。
- 買い上げの可否は会社の制度による。制度がない場合に請求できるとは限らない。
- 消化を申し出た結果として引き継ぎが終わらない、という状態を作らない。順序を先に決める。

## 空白期間があるとき

退職日と入社日の間が空くと、次の手続きが自分側に発生する。**空白が1日でもあれば対象になりうる。**

| 項目 | 何が必要か |
| --- | --- |
| 健康保険 | 任意継続、国民健康保険、家族の被扶養者のいずれかを選ぶ。申請には期限がある |
| 年金 | 国民年金への切替 |
| 住民税 | 退職の時期によって、一括徴収か普通徴収かが変わる |
| 雇用保険 | 離職票の受領。失業給付を受けるかは、次の入社日が決まっているかで変わる |
| 企業年金・確定拠出年金 | 移換の手続きに期限がある |

**それぞれの期限と要件は時点で変わる。** 手続きの前に、市区町村、年金事務所、ハローワーク、加入している健康保険組合の公表内容を確認する。ここに書いてあることを確定した手続きとして扱わない。

## 受け取るもの・返すもの

| 受け取る | 何に使うか |
| --- | --- |
| 離職票 | 失業給付の手続き（次が決まっていれば不要なこともある） |
| 雇用保険被保険者証 | 次の勤務先に提出する |
| 源泉徴収票 | 次の勤務先での年末調整、または確定申告 |
| 年金手帳・基礎年金番号の通知 | 年金の手続き |
| 退職証明書 | 求めがあれば発行される。国民健康保険の手続きなどで使う |

| 返す | 注意 |
| --- | --- |
| 健康保険証 | 退職日の翌日以降は使えない |
| 社員証・入館証 | |
| 貸与されたPC・携帯・鍵 | データの取り扱いを会社の指示に従う |
| 名刺 | 自分の分と、受け取った分の扱いを確認する |
| 業務資料・データ | **持ち出さない。** 転職先で使う目的での複製は行わない |

## 引き継ぎと守秘

- 引き継ぎ資料は業務の範囲にとどめる。個人的な評価や人物評を書かない。
- **顧客情報、技術情報、社内資料を持ち出さない。** 転職先で使う目的の複製は、在職中の義務にも次の職場での立場にも関わる。
- 退職後も守秘義務が続く契約になっていることが多い。契約書の該当箇所を確認する。
- 競業避止の条項がある場合、内容と範囲を確認する。有効性の判断はここで下さない。

## 社外への連絡

顧客や取引先への連絡は、会社の方針に従う。個人の判断で先に伝えない。SNSでの公表の可否も、退職日と会社の方針を確認してから決める。

## スクリプト入力

`scripts/check_resignation_plan.py` は日程と手続きの確認状況を数えるだけで、退職の可否も適法性も判定しない。

```json
{
  "as_of": "2026-09-01",
  "offer_accepted": true,
  "current": {
    "contract_type": "indefinite",
    "notice_rule_source": "employment_rules",
    "notice_days_required": 30
  },
  "dates": {
    "intended_notice_date": "2026-09-05",
    "desired_last_day": "2026-10-31",
    "start_date_new": "2026-11-16",
    "paid_leave_days_remaining": 18
  },
  "items": [
    {"code": "confirm_rules", "status": "done"},
    {"code": "notice_to_manager", "status": "planned"},
    {"code": "rishokuhyo", "status": "confirmed"}
  ]
}
```

- `notice_rule_source` は `employment_rules`（就業規則を見た）/ `contract`（雇用契約書を見た）/ `unknown`。**見ていないなら `unknown` にする。** 一般論の日数で埋めない。
- `notice_days_required` は自社の規定の日数。確認できていなければ省略する。
- `items` の `status` は、手続き系が `done` / `planned` / `none`、書類と返却物が `confirmed` / `pending` / `not_applicable` / `unknown`。入れなかった項目は未着手・未確認として数えられる。
- `offer_accepted` は転職先の内定を承諾済みか。`true` 以外では、順序に関する注記が出る。

実行:

```bash
python3 scripts/check_resignation_plan.py input.json
```

出力の `schedule` は申出から退職日までの日数、就業規則の定めとの差、退職日までの平日数、有給の残日数との関係、退職日と入社日の空白日数。**平日数は土日を除いた概算で、祝日と会社の休日を含まない。** `flags` は日程と手続きの確認漏れ。
