# 辞退の進め方

## 順序

**受ける先を確定してから、他を辞退する。** 順序を逆にすると、どこにも行き先がない状態になりうる。

確定とは、口頭で「入社します」と言ったことではなく、**労働条件が書面で確認できている**ことを指す。`offer-terms-check` で条件を確認し、そのうえで承諾し、それから辞退の連絡に入る。

ただし、選考の途中で「もう受けない」と決めた先は、この順序に縛られない。受ける先が決まっていなくても、進める気がない選考は早く辞退してよい。

## 3つの段階を混ぜない

| 段階 | 何が起きているか | 伝え方 |
| --- | --- | --- |
| 選考途中の辞退 | まだ内定は出ていない | 早いほどよい。理由を詳しく述べる必要はない |
| 内定の辞退（承諾前） | 内定は出たが、承諾していない | 期限内に伝える。**期限を過ぎてから伝えない** |
| **承諾後の辞退** | 承諾を伝えたあとに撤回する | 先方の準備が進んでいる。**できるだけ早く、直接伝える** |

承諾後の辞退の法的な扱いは事案による。**ここで結論を出さない。** 実務として言えるのは、先方が受け入れ準備（社内手続き、他の候補者の見送り、備品や席の手配）を進めている段階だということまでである。心配がある場合は、専門家への相談を選択肢として残す。

## 経路ごとに誰へ伝えるか

| 経路 | 伝える相手 | 注意 |
| --- | --- | --- |
| 直接応募 | 採用担当者 | |
| エージェント経由 | **担当のエージェント** | 企業へ直接連絡すると経路が二重になる。エージェントに伝え、企業への連絡を任せる |
| 学校推薦 | 企業と**学校の就職課の両方** | 推薦枠は後続の応募者に影響しうる。学校の指示を先に確認する |
| 社員紹介（リファラル） | 企業と**紹介者の両方** | 紹介者が企業からの連絡で知る形にしない。自分から先に伝える |
| スカウト媒体 | 媒体の連絡機能か、担当者 | |

**学校推薦の辞退は、自分だけの問題ではない。** 学校ごとに扱いが違うため、就職課に先に相談する。ここで「辞退できる／できない」を断定しない。

## 伝え方

- 期限内に、決めたらできるだけ早く伝える。**返事を先延ばしにして期限を過ぎさせない。**
- 手段は、先方の指定があればそれに従う。指定がなければ、選考中の連絡に使ってきた手段に合わせる。承諾後の辞退は、電話などの直接伝わる手段を先にする。
- **辞退の理由を詳しく述べる義務はない。** 伝えるかどうかは自分で決める。伝える場合も、他社の社名や提示条件を出す必要はない。
- 嘘の理由を作らない。言いたくないことは「社内で検討した結果」「他の機会を選ぶことにした」の範囲でよい。
- 感謝と、時間を割いてもらったことへの言及があれば足りる。長い説明は要らない。

## 引き止めと、他社辞退の要求

辞退を伝えたあとに引き止められることがある。また、内定と引き換えに**他社の辞退を求められる**ことがある。

- **応じる義務はない。** 求められた内容と時期を、事実として記録する。
- その場で結論を出さない。「持ち帰って検討します」と言ってよい。
- 条件の上積みが提示された場合、口頭の提示は条件ではない。書面での明示を求めるかどうかを含めて、`offer-terms-check` で扱う。
- 内定を出す条件として他社の辞退を求められた場合、それに応じるかどうかは自分で決める。**こちらで「応じるべき」とも「拒否すべき」とも書かない。** 記録を残すことだけを勧める。

## 残っているものの整理

辞退の連絡と同時に確認する。

- 預けた書類（成績証明書、卒業見込証明書、職務経歴書の原本、健康診断書）の返却または破棄
- 交通費・宿泊費の精算が途中で終わっていないか
- 貸与された物（入館証、テスト端末、資料）の返却

**「もう辞退したから連絡しない」で終わらせない。** 返却や精算が残っていると、後で連絡が必要になる。

## スクリプト入力

`scripts/check_decline_plan.py` は順序と連絡先と残務を確認するだけで、辞退の可否も文面の適切さも判定しない。

```json
{
  "as_of": "2026-09-01",
  "accepting": {
    "company": "架空A社",
    "accepted": true,
    "terms_in_writing": true,
    "start_date": "2026-11-01"
  },
  "declining": [
    {
      "id": "d1",
      "company": "架空B社",
      "stage": "offered_not_accepted",
      "route": "agent",
      "deadline": "2026-09-05",
      "notice_sent": false,
      "loose_ends": {"documents_held": true},
      "pressured_to_decline_others": false
    }
  ]
}
```

- `accepting` は受ける先。**`accepted` と `terms_in_writing` の両方が `true` になって初めて、確定として扱われる。** まだなら省略する。
- `stage` は `in_selection` / `offered_not_accepted` / `offered_accepted` / `unknown`。**混ぜない。**
- `route` は `direct` / `agent` / `school_recommendation` / `referral` / `platform` / `unknown`。経路ごとに、本人以外への連絡が必要かが出る。
- `loose_ends` は `documents_held`（書類を預けている）/ `expenses_unsettled`（精算が残っている）/ `items_borrowed`（借りている物がある）。
- `pressured_to_decline_others` は、他社の辞退を求められたか。記録のための項目であって、対応を決める項目ではない。

実行:

```bash
python3 scripts/check_decline_plan.py input.json
```

出力の `flags` は、伝える前に確認すべき点。`extra_contact` は、経路ごとに企業以外へ連絡が要るかどうか。
