# 入社後の段取りの進め方

## 何を作るか

成果物は、入社後の働き方を左右する**期待と約束の一覧**と、それを**誰といつ確かめるか**の日程である。入社後の成果の計画でも、職場に馴染むための心得でもない。

面接や条件の交渉で聞いたことは、入社後に担当者が替わったり、言った人と配属先が違ったりして、そのままにしておくと確かめる手段がなくなる。入社前後の早い時期に、相手と共有する形で確かめる。

## 並べる項目

| 項目 | 例 | よく抜けるところ |
| --- | --- | --- |
| 担当範囲 | 担当する顧客、製品、業務の範囲 | どこまでが自分の範囲で、どこからが他の人か |
| 最初に任される仕事 | 入社後1〜3か月の仕事 | 誰から引き継ぐか、いつまでに |
| 評価の基準 | 何ができたら評価されるか | 試用期間の基準と通常の評価の基準が別か |
| 将来の役割 | 「半年後にリーダー」「いずれ企画に」 | 時期と条件。誰が決めるか |
| 勤務場所・勤務形態 | 拠点、在宅日数、勤務時間帯、フレックス | 試用期間中も同じか。チームの運用と合っているか |
| 配属 | 部署、チーム、直属の上長 | 入社時点で確定しているか |
| 研修・入社前の課題 | 入社前研修、事前学習 | 賃金の扱い、参加の要否 |
| 交渉で合意したこと | 給与の見直し時期、入社日 | 改訂された書面に入っているか |

各項目に、**誰が・いつ・どこで言ったか**（出典）と、書面にあるかを付ける。言った人の名前は、確かめる相手を決めるためにだけ使う。言った人が分からない場合は、分からないと書く。

同じ条件について出典が複数ある場合（エージェントの「フルリモート可」と通知書の就業場所）は、**同じ項目名で別々の行にする。** 項目名が違うと食い違いが見えなくなる。

## 3つに分ける

| 区分 | 何を指すか | 扱い |
| --- | --- | --- |
| 書面にある | 労働条件通知書、雇用契約書、内定通知書、職務記述書に書かれている | 入社後の運用が書面と合っているかを確かめる |
| 口頭だけ | 面接、面談、エージェント経由、交渉の電話で聞いた | 確定した条件として扱わない。上長と共有して確かめ、合意した内容を自分で記録する |
| 測り方がない | 「成果を出してほしい」「早く戦力に」 | 何ができたら達成かを上長と決める。こちらで基準を作らない |

出典によって内容が違う項目（面接では在宅週3日、書面には「会社の定めによる」）は、どちらが正しいかを推測しない。確かめる項目にする。

## 試用期間

確かめること:

- 期間（開始日と終わりの日）
- 期間中の給与、雇用形態、勤務形態が本採用後と同じか（3つは別々に確かめる。給与だけ同じと書かれていることがある）
- 本採用の判断基準と、判断する人
- 延長があり得るか、その条件

判断基準が示されていない場合、入社後の早い時期に上長と確かめる。**試用期間の終わり近くになって初めて基準を知る、という状態を避ける。** 試用期間の定めや判断の適法性は判定しない。気になる点は確認事項として残し、相談先を示す。

## 確かめる場

| 時期 | 主な相手 | 確かめること |
| --- | --- | --- |
| 入社前 | 採用担当者、人事 | 書面の不足、入社日の段取り、手続き書類、初日の集合場所と時間、入社前の課題の扱い |
| 入社初週 | 直属の上長 | 担当範囲、最初の仕事、期待の共有、勤務形態の運用、試用期間の基準 |
| 入社1か月前後 | 直属の上長 | 最初の仕事の進み方、測り方の合意、口頭の約束の扱い |
| 試用期間の終わりの前 | 直属の上長 | 本採用の基準に照らした現在地 |

時期は目安で、会社の面談の仕組みがあればそれに合わせる。**確かめる場が試用期間の終わり近くにしかない状態を避ける**ことだけは守る。

質問は、確かめる形にする。「面接で◯◯と伺いました。入社後の進め方として、この理解で合っていますか」のように、聞いた内容と相手を示し、相手が訂正できる余地を残す。

## 前職との線引き

前職の資料、顧客情報、技術情報、社内の人脈情報を新しい職場に持ち込まない。前職の経験は本人の知識として使うにとどめる。前職の顧客に新しい職場から連絡する計画を手伝わない。退職時の誓約書に競業避止や勧誘禁止の定めがある場合は、その存在を確認事項に残す（有効性は判断しない）。

## スクリプト入力

`scripts/plan_onboarding.py` は、日付と期待の区分と確かめる場の有無を並べるだけで、試用期間の評価も、適法性も判定しない。

```json
{
  "employer": "架空システム株式会社",
  "as_of": "2026-10-15",
  "start_date": "2026-11-01",
  "written_terms": true,
  "probation": {
    "exists": true,
    "months": 3,
    "criteria_known": false,
    "conditions_same": {"pay": true, "employment_type": null, "work_style": null}
  },
  "expectations": [
    {
      "id": "x1",
      "topic": "勤務場所",
      "content": "週3日在宅可",
      "source": "interview",
      "said_by": "配属先の課長",
      "said_on": "2026-08-20",
      "confirm_with": "manager"
    },
    {
      "id": "x3",
      "topic": "勤務場所",
      "content": "就業場所：本社および会社が指定する場所",
      "source": "notice",
      "confirm_with": "recruiter"
    },
    {
      "id": "x4",
      "topic": "入社前の課題",
      "content": "課題図書を読んでおく",
      "source": "interview",
      "before_start": true,
      "confirm_with": "recruiter"
    },
    {
      "id": "x2",
      "topic": "最初の担当",
      "content": "既存顧客10社の運用を引き継ぐ",
      "source": "job_description",
      "measurable": false,
      "due": "2027-01-31",
      "confirm_with": "manager"
    }
  ],
  "pre_start_tasks": [
    {"label": "入社手続き書類の提出", "due": "2026-10-25", "status": "planned"}
  ],
  "checkpoints": [
    {"label": "採用担当者への確認", "date": "2026-10-20", "with": "recruiter", "topics": ["x3", "x4"]},
    {"label": "上長との初回面談", "date": "2026-11-02", "with": "manager", "topics": ["x1", "x2"]}
  ]
}
```

- `written_terms` は労働条件を書面（電子交付を含む）で受け取っているか。不明なら `null`。
- `probation.conditions_same` は、試用期間中の条件が本採用後と同じかを `pay`（給与）/ `employment_type`（雇用形態）/ `work_style`（勤務形態）ごとに `true` / `false` で入れる。分からないものは省略する。
- `probation.months` か `probation.end_date` のどちらかを入れる。`months` だけのときは、入社日から数えた終わりの日を計算する。会社の定めと違う場合は `end_date` を入れる。
- `expectations[].source` は `notice` / `offer_letter` / `job_description` / `posting` / `interview` / `agent` / `negotiation` / `unknown`。最初の3つだけを書面として扱う。求人票（`posting`）は書面として扱わない。
- `topic` は、同じ条件について出典が複数あるときは同じ文字列にする。食い違いの検出は `topic` が一致する行どうしで行う。
- `measurable` は、担当範囲・将来の役割・評価の基準のような期待について、何ができたら達成かが決まっていれば `true`、決まっていなければ `false`。勤務場所のように測る対象でない項目は省略する。`false` の項目だけを注記する。
- `before_start` は、入社前にやるよう求められた作業（課題、研修、事前学習）なら `true`。期限が入社日より前の項目も同じ扱いになる。
- `confirm_with` と `checkpoints[].with` は `recruiter` / `manager` / `hr` / `agent` / `undecided`。
- `confirmed` は、入社後に上長などと確かめ終えたら `true` にする。
- `checkpoints[].topics` は、その場で確かめる `expectations` の `id`。
- 上長（`manager`）と確かめる場が1つも入っていないと、入社日と試用期間から上長との場の目安の日付を `suggested_checkpoints` に出す。試用期間の基準を確かめる場は、上長との場だけを数える。

実行:

```bash
python3 scripts/plan_onboarding.py input.json
```

出力の `dates` は入社までの日数と試用期間の終わり、`expectations` は項目ごとの書面の有無、`conflicts` は出典間の食い違い、`flags` は入社前後に決めること。
