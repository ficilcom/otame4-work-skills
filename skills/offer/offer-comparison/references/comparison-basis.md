# 比較の基準

## 提示年収をそのまま並べない

日本の内定で示される「年収」は、企業ごとに含むものが違う。並べる前に必ず分解する。

| 構成要素 | 変動するか | 比較での扱い |
| --- | --- | --- |
| 基本給 | しない | 昇給・賞与・退職金の算定基礎になる。最も重い |
| 固定手当（役職、地域、資格） | しない | 基本給に足して「固定的に受け取る額」にする。ただし算定基礎に入らないことがある |
| 固定残業代（みなし残業代） | しない | 金額は固定だが、対応する労働時間が違う。時間数とセットで読む |
| 賞与 | 保証がなければ変動する | 保証されていない賞与を提示年収に含んでいる場合、その額は約束ではない |
| 通勤手当 | — | 実費の補填であり、収入の比較に入れない |
| 住宅補助 | 制度次第 | 課税か非課税かで手取りへの効き方が変わる。参考値として別に置く |
| 退職金・企業年金 | — | 年額に換算しない。制度の有無と種類を記載のまま並べる |

## 揃える4つの数字

1. **基本給＋固定手当の年額** — 固定残業代と賞与を抜いた部分。昇給と退職金の基礎になるため、長く働くほど効く。
2. **変動しない年額** — 基本給＋固定手当＋固定残業代に、保証されている賞与だけを足したもの。**確実に受け取る額**として比較できる唯一の数字。
3. **想定年間労働時間** — 所定労働時間＋みなし残業時間。固定残業代の多い内定は、この時間が長い。
4. **時給換算** — 上の2つを3で割る。提示年収での時給と、変動しない年額での時給を両方出す。

**提示年収が高い内定が、変動しない年額でも時給でも高いとは限らない。** 分解して初めて逆転が見える。分解できない項目がある内定は、その項目を比較から落とす。推定値で埋めない。

## 賞与の扱い

- 「賞与年2回（実績4.5か月）」は実績であって保証ではない。業績連動なら変動する。
- 「賞与込み年収」の提示で賞与が保証されていない場合、提示年収と提示年収を並べた比較は成立しない。
- 保証されているかどうかが不明なら `guaranteed` を省略する。スクリプトは「変動しない年額」を出さず、確認事項として残す。
- 入社初年度は賞与が満額出ないことがある。初年度と2年目以降で条件が違う場合は、別の内定として並べるのではなく、同じ内定の注記として書く。

## 金額にならない条件

金額に換算できないものを金額に換算しない。点数化もしない。並べるだけにする。

- 勤務地、転勤の範囲、リモートの可否と出社頻度
- 労働時間制度、残業の実態、休日数
- 業務内容、裁量の範囲、配属先の確定状況
- 契約期間、試用期間の条件
- 事業の状況、体制、直属の上長

**重みは利用者が決める。** 「年収は下がるが勤務地が動かない」の優劣を、こちらで判定しない。利用者が重視する軸を聞き、その軸で並べ替えて見せるところまでにする。

## 手取りについて

額面の比較を手取りの比較として扱わない。手取りは、扶養、住所地、社会保険の加入先、住宅補助の課税扱い、企業年金の掛金で変わる。概算を出す場合も前提を明示し、確定した数字として示さない。

## スクリプト入力

`scripts/compare_offers.py` は提示条件を同じ基準に並べ替えるだけで、順位も総合点も出さない。

```json
{
  "as_of": "2026-09-01",
  "offers": [
    {
      "label": "A社",
      "employment_type": "正社員",
      "compensation": {
        "basis": "written_notice",
        "annual_total": 5400000,
        "components": {
          "monthly_base": 300000,
          "fixed_allowances_monthly": 20000,
          "fixed_overtime": {"monthly_amount": 60000, "hours": 30, "included_in_annual": true},
          "bonus": {"annual_amount": 840000, "guaranteed": false, "included_in_annual": true}
        }
      },
      "working_hours": {"daily_scheduled_hours": 8, "monthly_working_days": 20},
      "other": {
        "commute_allowance_monthly": 15000,
        "housing_support_monthly": 20000,
        "retirement_plan": "確定拠出年金あり"
      },
      "non_monetary": [{"topic": "勤務地", "value": "東京。転勤の範囲は全国の支社"}]
    }
  ]
}
```

- `basis` は `written_notice`（労働条件通知書・雇用契約書）/ `offer_letter` / `verbal` / `posting` / `estimated` / `unknown`。書面で確認していない条件を `written_notice` にしない。書面かどうかの確認は `offer-terms-check` で行う。
- `annual_total` は**提示された年収を記載どおり**に入れる。内訳から計算し直した額を入れない。両方あれば、内訳の合計と提示額のずれを検出できる。
- `included_in_annual` は、その要素が `annual_total` に含まれているか。不明なら省略する。0で埋めない。
- `bonus.guaranteed` は、支給が保証されているか。「実績◯か月」は保証ではない。不明なら省略する。
- 固定残業代がない内定は `fixed_overtime` に `{"monthly_amount": 0, "hours": 0, "included_in_annual": true}` を入れる。ブロックごと省略すると「有無が不明」として扱われる。
- `non_monetary` は金額にならない条件。スクリプトは並べるだけで、評価も点数化もしない。

実行:

```bash
python3 scripts/compare_offers.py input.json
```

出力の `metrics` は指標ごとの各社の値と開き、`not_comparable` はデータが欠けていて比較できない指標、`flags` は並べる前に確認すべき点。`comparable` が `false` の指標を、欠けている会社を除いて比較しない。
