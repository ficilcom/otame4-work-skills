# 受け取りと確認事項

## 最初に固定すること

質問を始める前に、利用者が渡した原稿・募集要項・求人票を読む。そのうえで、以下のうち原稿から読み取れないものだけを聞く。

| 項目 | 用途 | 未確認のときの扱い |
| --- | --- | --- |
| 応募区分（新卒 / 中途 / インターン） | 評価軸の選択 | 聞くまで改稿方針を確定しない |
| 応募企業・職種・募集要項のURLまたは本文 | 設問意図と求める要件の照合 | `unknown`。要件との整合は判定しない |
| 設問文（原文のまま） | 設問への適合判定 | 要約された設問で判定しない |
| 制限文字数と数え方 | 分量調整 | `unknown`。上限ぎりぎりの調整はしない |
| 提出期限 | 改稿範囲の決定 | 全面書き直しを既定にしない |
| 提出形式（Webフォーム / PDF / 手書き） | 改行・体裁の扱い | 改行前提の構成にしない |
| 併願状況・使い回しの有無 | 他社流用表現の検出 | 指摘の根拠にしない |

## 評価軸

設問ごとに、次の順で見る。順番を入れ替えない。

1. **設問適合** — 聞かれたことに答えているか。志望動機を聞かれて自己PRを書いていないか。
2. **事実の裏づけ** — 行動、役割、期間、規模、成果が具体的か。主語が「私」になっているか（チームの成果を自分の成果として書いていないか）。
3. **一貫性** — 他の設問、履歴書、職務経歴書との間で時期・役割・志望の説明が矛盾していないか。
4. **可読性** — 一文の長さ、構成、結論の位置、冗長表現。
5. **体裁** — 表記ゆれ、敬体・常体の統一、誤字。

## 証拠の区別

主張ごとに次を区別し、`unknown` を 0 や達成に置き換えない。

- `confirmed` — 利用者が資料（成績、評価、社内数値の公開範囲など）で示した事実
- `reported` — 利用者の記憶による申告
- `estimated` — 利用者が置いた推定。推定であることを本文に残すか、書かないかを利用者に選ばせる
- `unknown` — 未確認。断定形にしない

## 新卒と中途の重心の違い

| | 新卒 | 中途 |
| --- | --- | --- |
| 中心に置くもの | 行動の具体性、意思決定の理由、学び | 担当範囲、再現性のある手順、数値成果 |
| 分量配分 | 状況説明を短く、行動を厚く | 前提説明を短く、成果と役割を厚く |
| 職務経歴書 | 通常不要 | 応募職種に合わせて並べ替える |
| 注意 | 「頑張った」に留まる記述 | 守秘情報、チーム成果の自己成果化 |

## スクリプト入力

`scripts/check_entry_sheet.py` は文字数と表層的な特徴だけを測る。内容の判定はしない。

```json
{
  "count_rule": "with_whitespace",
  "count_rule_confirmed": false,
  "documents": [
    {
      "id": "gakuchika",
      "question": "学生時代に最も力を入れたことを教えてください。",
      "limit_chars": 400,
      "min_chars": 320,
      "answer": "（原稿本文）"
    }
  ]
}
```

- `count_rule` — `with_whitespace`（改行を除き空白を数える）または `without_whitespace`（空白をすべて除く）。
- `count_rule_confirmed` — 企業指定を確認できたときだけ `true`。`false` のままなら報告に未確認の注記が入る。
- `limit_chars` を省略すると長さは `unknown` になる。`min_chars` の既定は上限の 80%。

実行:

```bash
python3 scripts/check_entry_sheet.py input.json
```

出力の `length_status` は `ok` / `under_target` / `over_limit` / `unknown`、`redundant_phrase_candidates` は削減候補であって誤りの指摘ではない。
