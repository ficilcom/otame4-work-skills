# 出典の階層と当たり先

## 階層

上から順に当たる。下の階層は上の階層を置き換えない。

| tier | 何が入るか | 扱い |
| --- | --- | --- |
| `primary_filing` | 有価証券報告書などの法定開示、決算公告、登記情報、国税庁の法人番号公表サイト | 確認済みの事実として書ける |
| `company_official` | 会社HP、IR資料、決算説明資料、統合報告書、採用ページ、自社発表のプレスリリース | 確認済みの事実として書ける（発信者が企業自身である点は明記する） |
| `regulated_public` | 行政が公開する職場情報、公共職業安定所の求人、労働法令違反の公表事案 | 確認済みの事実として書ける |
| `journalism` | 報道機関の記事 | 「報道による」と明記する。企業の否認があれば併記する |
| `user_provided` | 利用者が選考で受け取った書面、面談メモ、スカウトメール | 「利用者提供」と明記する。第三者に検証できない |
| `unverified` | 転職口コミサイト、まとめ記事、SNS、匿名掲示板 | 事実として書かない。面接で確認する論点としてのみ残す |

## 日本企業を調べるときの当たり先

制度もURLも変わるため、その場で最新を確認する。ここに挙げたのは探し方の順序であって、内容の保証ではない。

- **法定開示** — 金融庁の開示システム（EDINET）。有価証券報告書には、事業の内容、セグメント別業績、従業員数と平均勤続年数、平均年間給与、事業等のリスクが載る。**上場企業と一部の大企業しか提出していない**ため、中小企業では空振りになる。
- **決算公告** — 株式会社は会社法上、定時株主総会後に決算を公告する義務がある。官報、日刊新聞、または自社サイトの電子公告のいずれか。ただし実務上は未実施の会社も多く、見つからないこと自体は違法性の証拠にならない。
- **法人の実在と商号** — 国税庁の法人番号公表サイトで、正式商号、本店所在地、変更履歴が確認できる。同名企業やグループ会社の取り違えを潰すのに使う。
- **会社の公式情報** — 会社概要、IR、決算説明資料、統合報告書、採用サイト、プレスリリース。事業の説明は企業自身の言葉なので、業績の裏づけと合わせて読む。
- **行政の職場情報** — 厚生労働省が運営する職場情報の総合サイトに、平均勤続年数、有給休暇取得率、育児休業取得率などが載る場合がある。企業の任意公開に依存するため、掲載がないこと自体は評価材料にならない。
- **新卒募集企業の職場情報** — 若者雇用促進法により、新卒者を募集する企業は求めに応じて職場情報（募集・採用状況、職業能力の開発向上、雇用管理）を提供する義務がある。採用ページに掲載がなければ、応募者として問い合わせられる。
- **公共職業安定所の求人** — 同じ企業の求人が民間サイトと条件が違うことがある。差分は確認すべき論点になる。
- **法令違反の公表** — 厚生労働省が労働基準関係法令違反の事案を公表している。掲載の有無は時点で変わるため、確認日を必ず記録する。
- **報道** — 資金調達、買収、事業撤退、不祥事。一次資料が出ていないか先に探す。

## 取得できないときの代替

Web取得の手段がない、またはページに到達できない場合は、次の順で切り替える。空欄を推測で埋めない。

1. 利用者にURLか本文を貼ってもらう。
2. 何が確認できていないかを明示し、その項目を `unknown` のまま報告に残す。
3. 面接や問い合わせで直接確認する質問として文面を用意する。

## 調べる項目

`check_source_coverage.py` の既定トピックに対応する。

| topic | 内容 |
| --- | --- |
| `legal_entity` | 正式商号、法人番号、本店所在地、設立、資本金、グループ構造、募集元の法人 |
| `business_model` | 何を誰に売って稼いでいるか、収益の柱、主要な取引先や顧客層 |
| `financials` | 売上、利益、従業員数、平均勤続年数。決算期と連結/単体を必ず添える |
| `organization` | 事業部門、開発体制、拠点、募集職種が属する組織 |
| `role_context` | 募集職種が事業のどこに位置し、なぜ今募集しているか |
| `working_conditions` | 勤務地、勤務時間制度、休日、リモートの可否、公開されている待遇 |
| `risks` | 訴訟、行政処分、法令違反の公表、希望退職、事業撤退、大株主の変動 |
| `recent_events` | 直近1〜2年の資金調達、新規事業、体制変更、経営陣の交代 |

## スクリプト入力

`scripts/check_source_coverage.py` は、集めた主張の出典の強さ・鮮度・網羅・矛盾だけを機械的に整理する。内容の正しさは判定しない。

```json
{
  "company": "架空システム株式会社",
  "as_of": "2026-08-28",
  "claims": [
    {
      "id": "fin-1",
      "topic": "financials",
      "statement": "2026年3月期の連結売上高は前期比で増加している",
      "sources": [
        {
          "url": "https://example.com/yuho.pdf",
          "publisher": "EDINET",
          "tier": "primary_filing",
          "published_on": "2026-06-25",
          "retrieved_on": "2026-08-28"
        }
      ]
    },
    {
      "id": "cond-1",
      "topic": "working_conditions",
      "statement": "残業が多いという書き込みが複数ある",
      "sources": [
        {
          "url": "https://example.com/review",
          "tier": "unverified",
          "retrieved_on": "2026-08-28"
        }
      ],
      "conflicts_with": ["cond-2"]
    }
  ]
}
```

- `tier` は上の表の6種類。`url` は `user_provided` 以外では必須。
- `published_on` を省略すると鮮度は判定されず、「時点不明」として注記される。0や推定日で埋めない。
- `conflicts_with` に矛盾する主張のIDを書くと、双方が `contested` になる。

実行:

```bash
python3 scripts/check_source_coverage.py input.json
```

出力の `evidence` は `confirmed` / `reported` / `unverified` / `unknown`。`must_not_state_as_fact` に入ったIDは、報告書で事実として書いてはならない。`coverage_gaps` は、確認済みの事実が1件もないトピックを示す。
