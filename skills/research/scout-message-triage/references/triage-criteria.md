# 仕分けの基準

## 何を見るか

スカウトは**文面の熱意ではなく、開示されている事実**で仕分ける。丁寧な文面のテンプレートもあれば、そっけない個別連絡もある。文章の印象を判断材料にしない。

| 見るところ | なぜ |
| --- | --- |
| 企業名が明かされているか | 明かされていなければ、企業研究も求人票の読み解きもできない |
| 給与・勤務地・雇用形態・業務内容の記載 | 欠けている項目は、そのまま確認事項になる |
| 経歴に触れた記述があるか | 一斉送信か、経歴を読んだ上での連絡かの手がかり |
| 年収の書き方 | 「最大」「可能」は提示ではない |
| 詳細を見るのに登録・面談が必要か | 経歴を渡す前に、渡す範囲を決める必要がある |
| 返信期限 | 急がされること自体は、条件の良さではない |
| 同じ企業を複数経路から受けていないか | 経路が重なると応募が重複しうる |

**個別化されていないスカウトを、それだけの理由で落とさない。** 一斉送信でも条件が具体的なものはあり、個別化されていても条件が空のものもある。個別化の有無は「文面を根拠にしない」ための情報であって、優劣ではない。

## 企業名が伏せられている場合

「大手メーカー」「急成長中のSaaS企業」のような書き方では、次のどれも確認できない。

- 実在する求人か
- 募集元と実際の就業先が同じか
- 過去に応募した企業と同じでないか
- 現職・取引先と競合しないか

**企業名を確認するまで、経歴書を渡さない。** 企業名は、聞けば答えられることが多い。答えられない場合、その理由を確認する。

## 年収の書き方

| 書き方 | 意味 |
| --- | --- |
| 「500万〜700万」 | レンジの提示。ただし適用条件は別途確認する |
| 「最大900万」 | 上限だけの提示。誰にいくら出るかは書かれていない |
| 「年収600万も可能」 | 提示ではない。可能性の表現 |
| 記載なし | 確認事項 |

**上限や可能性の表現を、提示された条件として扱わない。** 給与の分解は、企業名と求人票が手に入ってから `job-posting-analysis` で行う。

## 経歴を渡す前に

エージェントへの登録、面談、プラットフォームでの経歴公開は、いずれも**個人情報を渡す行為**である。渡す前に決める。

- 渡す範囲（職務経歴書の全文か、要約か）
- 現職の社名を出すか
- 他社の選考状況を伝えるか（伝える義務はない）
- 個人情報の取り扱いと、第三者提供の有無

**エージェントに現職の社名や他社の選考状況を伝えるかは、利用者が決める。** こちらで「伝えた方がスムーズ」といった助言をしない。

## 同じ企業を複数経路から受けたとき

同じ企業のスカウトが、複数のエージェントや媒体から届くことがある。**どの経路で応募するかを先に決める。** 経路が重なると、企業側で応募が重複し、扱いが面倒になることがある。

どの経路を選ぶかの判断材料は、利用者が持っている情報（担当者との関係、これまでのやりとり）に依存する。**こちらで経路を推奨しない。** 重複しているという事実と、先に決める必要があることを示すまでにする。

## 返信

- 返信の要否と期限を記録する。**期限が短いこと自体を、良い求人の根拠にも、悪い求人の根拠にもしない。**
- 見送る場合も、返信するかどうかは利用者が決める。
- 返信の文面は下書きできるが、**送信しない。**

## スクリプト入力

`scripts/triage_scouts.py` は記載の有無と重複を数えるだけで、求人や企業の評価はしない。

```json
{
  "as_of": "2026-09-01",
  "scouts": [
    {
      "id": "s1",
      "from": "agent",
      "company": "架空システム株式会社",
      "role": "バックエンドエンジニア",
      "received": "2026-08-28",
      "reply_deadline": "2026-09-05",
      "conditions": {"pay": true, "location": true, "employment_type": true, "duties": true},
      "personalized": ["職務経歴書の在庫管理の記述に言及している"],
      "pay_claim_type": "range",
      "requires_registration": false,
      "user_interest": "yes"
    }
  ]
}
```

- `from` は `company`（企業から直接）/ `agent` / `platform` / `unknown`。
- `company` は明示されている場合のみ入れる。**「大手メーカー」のような表現を企業名として入れない。** 省略すると「企業名なし」として扱われる。
- `conditions` の4項目は、**その条件が文面に書かれているか**。内容の良し悪しではない。
- `personalized` は、経歴に触れた記述の実例。テンプレートなら空にする。
- `pay_claim_type` は `range` / `maximum`（上限のみ）/ `possible`（「可能」の表現）/ `none`。
- `user_interest` は利用者の関心。確認していなければ省略する。**こちらで判断しない。**

実行:

```bash
python3 scripts/triage_scouts.py input.json
```

出力の `routing` は次に何をする段階かの振り分けで、**応募すべきかどうかではない。**

| routing | 意味 |
| --- | --- |
| `needs_company_name` | 企業名を確認するまで進められない |
| `needs_conditions` | 条件の記載が欠けている。確認事項にする |
| `ready_for_posting_analysis` | 企業名と条件が揃っている。`job-posting-analysis` に渡せる |
| `user_decision_pending` | 記載は揃っている。関心の有無を利用者が決める段階 |
| `declined` | 利用者が見送ると決めたもの |
