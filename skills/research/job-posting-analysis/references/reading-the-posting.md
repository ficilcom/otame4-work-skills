# 記載の読み方

## 書き出す項目

記載どおりに写す。書かれていない項目は `unknown` にする。**空欄を職種名や業界の常識で埋めない。**

| 項目 | 見るところ | よくある欠落 |
| --- | --- | --- |
| 募集元の法人 | 会社名、派遣・請負の別 | 実際の就業先が別法人 |
| 雇用形態 | 正社員 / 契約社員 / 業務委託 / 派遣 | 試用期間中の雇用形態と条件 |
| 就業場所 | 所在地、転勤の有無、リモートの可否 | 「本社ほか」の範囲、出社頻度 |
| 業務内容 | 具体的な担当範囲 | 「その他付随する業務」の実際の比重 |
| 労働時間制度 | 標準 / フレックス / 裁量労働 / シフト | コアタイム、清算期間、裁量労働の適用職種 |
| 所定労働時間 | 1日の時間、月の勤務日数 | 休憩を含むか |
| 給与 | レンジ、内訳、固定残業代、賞与 | 下限・上限の適用条件 |
| 昇給・賞与 | 実績の記載 | 「業績による」だけの記載 |
| 要件 | 必須 / 歓迎 | どちらか区別されていない |
| 選考 | 回数、期間、勤務条件の提示時期 | 労働条件通知書がいつ出るか |

## 給与の分解

日本の求人票の「年収」は、次のどれを含むかで意味が変わる。求人票の文面で確定できないものは確定させない。

1. **固定残業代（みなし残業代）** — 提示年収に含まれることが多い。含む場合、その分の労働は提示額の中に織り込まれている。時間数と金額の記載を探す。両方揃わないと基本給を分離できない。
2. **賞与** — 「年収」に含む提示と、月給ベースの提示がある。含む場合、賞与は業績連動で変動しうる。
3. **各種手当** — 住宅手当、地域手当などをレンジに含めている場合がある。
4. **レンジの適用条件** — 上限が何年目の誰に適用されるか。中途採用では前職給与や等級で決まることが多い。

比較するときは、**固定残業代を除いた基本給**と、**みなし残業時間を含めた想定労働時間での時給**に揃える。提示年収のまま並べない。

## 労働時間制度

| 制度 | 見るところ |
| --- | --- |
| 標準 | 所定労働時間、残業の実績記載 |
| フレックスタイム | コアタイムの有無、清算期間 |
| 裁量労働制 | 対象業務が制度の適用対象か、みなし労働時間が何時間か |
| 固定残業代 | 時間数、金額、超過分が別途支給されると書かれているか |

固定残業時間が月45時間を超える設定は、特別条項なしの時間外労働の上限を超える前提になっている。スクリプトはこれを注記するが、**適法性は判定しない。** 記載の意味を確認する質問に変える。

## 要件の扱い

- 必須と歓迎が区別されていない求人票は、区別されていないこと自体を記録する。
- 「経験3年以上」のように確認できる要件と、「主体的に動ける方」のように確認できない要件を分ける。後者は選考基準として機能しないため、面接で具体化を聞く。
- 利用者の充足状況は `met` / `partial` / `unmet` / `unknown` で記録する。`unknown` を `unmet` に丸めない。
- **充足しない必須要件があっても、応募すべきでないとは書かない。** 日本の中途採用では必須要件が目安として運用されることも多い。判断は利用者が行う。

## スクリプト入力

`scripts/analyze_job_posting.py` は給与と要件の記載を分解するだけで、採用可能性も企業評価も出さない。

```json
{
  "title": "Webアプリケーションエンジニア",
  "employment_type": "正社員",
  "compensation": {
    "basis": "posted",
    "annual_min": 4200000,
    "annual_max": 7000000,
    "bonus_included_in_range": true,
    "fixed_overtime": {
      "included_in_range": true,
      "hours": 45,
      "annual_amount": 720000
    }
  },
  "working_hours": {
    "system": "standard",
    "daily_scheduled_hours": 8,
    "monthly_working_days": 20
  },
  "requirements": [
    {"text": "Webアプリケーションの開発経験3年以上", "kind": "must", "user_status": "met", "measurable": true},
    {"text": "チームでの開発経験", "kind": "must", "user_status": "unknown"}
  ],
  "open_questions": ["年収レンジの下限が適用されるのはどの等級か"]
}
```

- `basis` は `posted`（求人票の記載）/ `user_provided` / `estimated` / `unknown`。求人票にない金額を `posted` にしない。
- `fixed_overtime` を省略すると「固定残業代の有無が不明」として注記される。0で埋めない。
- `working_hours` は `monthly_scheduled_hours` を直接渡すか、`daily_scheduled_hours` と `monthly_working_days` から計算させる。
- `measurable` は、経験年数や具体的な成果物で確認できる要件のとき `true`。

実行:

```bash
python3 scripts/analyze_job_posting.py input.json
```

出力の `base_annual_*_excluding_fixed_overtime` は固定残業代を除いた年収、`hourly_min` / `hourly_max` はみなし残業を含めた想定労働時間での時給。分解に必要な記載が欠けている場合は `null` になり、`flags` に理由が入る。`null` を0や推定値に置き換えない。
