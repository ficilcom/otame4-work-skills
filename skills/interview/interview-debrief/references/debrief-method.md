# 振り返りの進め方

## いつ書き出すか

**面接の当日中に書き出す。** 質問の言い回し、自分がどう答えたか、相手が何と言ったかは、数日で急速に薄れる。日が経ってからの記録は、細部の再現度が落ちている前提で扱う。

思い出せないことは「思い出せない」と記録する。**思い出せないことを、それらしく再構成しない。** 再構成した記録を次の面接の材料にすると、実際とずれた準備をすることになる。

## 3つを分けて書き出す

| 何を | なぜ |
| --- | --- |
| 聞かれた質問と、答えられた度合い | 次の面接の準備に直結する |
| 逆質問と、得られた答え | 未解決の論点は次の段階に持ち越す |
| 企業側が述べたこと | 労働条件に関わるものは、書面確認の対象になる |

**手応え、印象、雰囲気は記録の対象にしない。** 面接官の表情や相槌から合否を読み取らない。読み取れないものを記録すると、次の判断が歪む。

## 答えられなかった質問の分け方

答えきれなかった質問は、原因で分けると次の打ち手が変わる。

| 区分 | 何が起きたか | 次にやること |
| --- | --- | --- |
| 準備していたのに答えきれなかった | 素材はあるが、話す順序や具体性の問題 | 話す順序を組み直す。素材を増やさない |
| 準備していなかった | 想定に入っていなかった | 素材を用意する。`interview-prep` に戻す |
| 提出書類の記述を聞かれて答えきれなかった | **書類の表現と事実がずれている** | 書類の表現を直す。次の面接までに最優先で処理する |

3つ目が最も重い。同じ書類で次の面接を受けるなら、同じ場所で同じことが起きる。

## 企業側の発言の扱い

面接で聞いた条件は、**書面ではない。**

- 残業時間、配属先、評価制度、給与の見込み、リモートの可否 — いずれも口頭で聞いた段階では確定していない。
- 求人票の記載と食い違う説明を受けた場合、どちらが適用されるかを確認する論点として残す。**その場で判断しない。**
- 誰が言ったかを記録する。現場の面接官が答えたことと、人事が答えたことでは、後で確認したときの扱いが変わる。
- 条件に関わる発言は `offer-terms-check` に渡す。書面での確認は内定後に行う。

## 次の連絡

結果の連絡時期と、誰から連絡が来るかを記録する。確認していない場合は、確認していないと記録する。**「たぶん1週間くらい」と埋めない。**

予定日を過ぎた場合、問い合わせるかどうかは利用者が決める。問い合わせの文面は下書きできるが、送信はしない。催促が不利に働くかどうかを予測しない。

## 記録の残し方

このスキルは、**既定では振り返りをファイルに保存しない。** 出力は会話の中で返す。

保存が必要な場合（複数社を並行している、面接が何回も続く）は、利用者から明示的に依頼されたときに限り、保存先と内容を示して承認を得る。保存する場合も、次の情報は書き込まない。

- 面接官の氏名、容姿、私生活に関する記述
- 面接官の人物評
- 他社の選考状況のうち、この面接の振り返りに不要なもの

## スクリプト入力

`scripts/review_interview.py` は起きたことを整理するだけで、手応えも合否の見込みも出さない。

```json
{
  "company": "架空システム株式会社",
  "stage": "first",
  "date": "2026-09-10",
  "as_of": "2026-09-10",
  "questions": [
    {"text": "在庫管理の刷新で担当した範囲は", "answered": "partial", "prepared": true, "from_documents": true},
    {"text": "チームで揉めたときにどうしたか", "answered": "none", "prepared": false}
  ],
  "questions_asked": [
    {"text": "評価はどの単位で決まるか", "result": "answered"},
    {"text": "配属先の残業実態", "result": "deferred", "note": "人事に確認すると言われた"}
  ],
  "employer_statements": [
    {
      "topic": "残業",
      "statement": "月20時間程度",
      "said_by": "現場マネージャー",
      "affects_conditions": true,
      "conflicts_with_posting": true
    }
  ],
  "next_steps": {"next_stage": "second", "result_promised_by": "2026-09-17", "who_contacts": "人事"}
}
```

- `answered` は `full` / `partial` / `none`。**自己評価の点数ではなく、聞かれたことに事実で答えられたかを入れる。**
- `prepared` は、その質問を想定して準備していたか。確認していないなら省略する。
- `from_documents` は、提出書類の記述についての質問か。
- `questions_asked` の `result` は `answered` / `partial` / `deferred`（後日回答と言われた）/ `unanswered`。
- `employer_statements` の `affects_conditions` は、労働条件に関わる発言か。`in_writing` は書面で示されたか（既定は `false`）。
- `as_of` を入れると、面接からの経過日数と、結果の連絡予定日の超過が出る。

実行:

```bash
python3 scripts/review_interview.py input.json
```

出力の `carry_forward` は、次の面接に持ち越す論点、書類の見直しに回す論点、条件の書面確認に回す論点の3つ。`flags` は次までに処理すべき点。**手応えや評価は出力に含まれない。**
