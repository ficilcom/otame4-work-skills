# 社内説明の組み立て方

## 誰に説明するか

おためし転職の受け入れを社内で通すとき、読み手は3通りある。同じ資料でも、先に答える問いが違う。

| 読み手 | 先に答える問い | 落としやすいもの |
| --- | --- | --- |
| 決裁者（部長、経営企画、人事） | いくらかかり、何が残り、いつ判断できるか | 受け入れ担当者の工数。現金だけを見て承認し、現場が回らない |
| 受け入れる現場（マネージャー、担当者） | 誰が何時間使い、通常業務がどう変わるか | 説明・レビュー・振り返りの時間。「空いた時間で」は工数の見積もりではない |
| 小規模企業の経営者（決裁者＝受け入れ担当） | この費用と時間で、何を確かめられるか | 自分の時間の原価。掲載料以外に自分の工数が最大の費用になることが多い |

小規模企業では決裁者と受け入れ担当が同じ人なので、資料は短くてよい。ただし社内工数を省かない。**経営者自身の時間が、この受け入れで最も高い費用になりうる。**

## 説明に必ず入れる項目

| 項目 | 書くこと | 出所 |
| --- | --- | --- |
| 目的 | 解決したい課題と、今回確かめたいこと（能力、協働、働き方） | `trial-work-design` の計画、利用者の発言 |
| 業務の範囲 | 対象作業、件数、完了基準、対象外 | 計画 |
| 候補者への支払い | 基準（時間単価・固定額・無償）、実働、予定額の幅、経費 | 計画 |
| 社内工数 | 役割ごとの時間、通常業務への影響、金額化するなら原価の基準 | 受け入れ担当者の見積もり |
| 周辺費用 | 掲載料、交通費、備品、アカウント。出所（公式・見積書・社内見込み・未確認） | 公式の料金表示、見積書 |
| 総額 | 現金で出る額と、社内工数を金額化した額を分けて示す | スクリプトの出力 |
| 予算との差 | 予算が現金だけか、社内工数まで含むかを明記して比べる | 社内の予算 |
| 採用に至らなかった場合に残るもの | 成果物、候補者からのフィードバック、受け入れ手順の整備、募集文の改善点 | 計画 |
| リスクと止める条件 | 資料の遅れ、範囲の拡大、途中確認で見直す条件、中止時の精算 | 計画の変更条件 |
| 判断者と期限 | 誰がいつまでに何を決めるか（予算、掲載、受け入れ開始） | 利用者 |

## 書き手が詰まりやすいところ

- **現金と社内工数を混ぜない。** 「候補者に24,000円」だけを総額にすると、担当者6時間が消える。金額化できない場合も、時間のまま総額の横に置く。
- **社内工数の原価を創作しない。** 社内に時間あたりの原価の基準があればそれを使う。なければ金額化せず、時間で示す。一部の役割だけ金額化すると、社内工数が小さく見える。
- **周辺費用は出所を付ける。** 掲載料をサービスの公式情報で確認したか、社内の見込みか、未確認かで、総額の確からしさが変わる。未確認の費用があるうちは、総額を確定額として書かない。
- **他の採用手段との比較は、確認済みの金額だけで行う。** 人材紹介の手数料、求人媒体の掲載料は、見積書や公式の料金表示がなければ金額を並べない。名前だけ挙げて「確認中」と書く。相場を記憶で置かない。
- **「採用できれば安い」を根拠にしない。** 採用の成否は予測しない。採用に至らなかった場合に残るものを、それ自体の価値として書く。
- **予算に合わせて工数を削らない。** 総額が予算を超えるなら、範囲を減らす案と予算を増やす案を並べる。説明や会議を無償枠に移して帳尻を合わせない。期間だけ延ばしても総額は減らない。
- **候補者の情報を稟議に入れない。** 応募者がすでにいる場合も、氏名や職歴を資料に書かない。必要なら仮名と、職務に関係する経験の有無だけにする。

## 予算が通らなかったとき

否決の理由を、金額、工数、目的の不明確さ、時期のどれかに分ける。金額なら範囲縮小の案を `trial-work-design` に戻して作り直す。工数なら受け入れ担当者の時間をどこから出すかを決める。目的なら、確かめたいことを1つに絞る。時期なら、次の判断日を決めて資料を残す。

## スクリプト入力

`scripts/summarize_trial_cost.py` は、候補者への支払い、社内工数、周辺費用を別々に合計し、予算と突き合わせるだけで、採用の成否も受け入れの是非も判定しない。

```json
{
  "as_of": "2026-09-17",
  "trial": {"label": "架空の記事改善おためし業務", "kind": "paid_work"},
  "candidate_pay": {
    "basis": "hourly",
    "hourly_rate": 2000,
    "hours": 12,
    "hours_max": 14,
    "expenses": 0
  },
  "company_hours": [
    {"role": "受け入れ担当（説明・合同レビュー・振り返り）", "hours": 4, "hourly_cost": 4000},
    {"role": "資料準備", "hours": 2, "hourly_cost": 4000}
  ],
  "other_costs": [
    {"label": "掲載料", "amount": 0, "source": "official", "note": "企業向けサイトの料金表示を確認した日付"},
    {"label": "交通費", "source": "unknown"}
  ],
  "budget": {"amount": 30000, "includes_company_hours": false},
  "alternatives": [
    {"label": "人材紹介", "source": "unknown"}
  ]
}
```

- `trial.kind` は `paid_work` / `learning_visit` / `unknown`。`paid_work` で `candidate_pay.basis` が `none` なら注意が出る。
- `candidate_pay.basis` は `hourly` / `fixed` / `none`（無償の見学・学習）/ `unknown`。**単価がなければ相場で埋めず、省略する。** 幅があるときだけ `hours_max` を入れる。
- `company_hours` は役割ごとの工数。`hourly_cost` は社内で使っている時間あたりの原価で、**社内に基準があるときだけ入れ、すべての役割に入っているときだけ金額化する。** 入っていない役割があれば時間のまま返る。例の 4000 は架空の基準であり、相場ではない。
- `candidate_pay.expenses` は候補者の経費（交通費など）の扱い。負担しないなら `0` と書く。省略すると未確認として扱い、現金の総額を確定させない。
- `other_costs.source` は `official`（公式の料金表示）/ `quote`（見積書）/ `estimate`（社内の見込み）/ `unknown`。`amount` を省略すると未確認として扱い、現金の総額を確定させない。例の掲載料 0 円は、企業向けサイトの料金表示を確認した場合の書き方であり、確認していなければ `source` を `unknown` にして `amount` を省く。
- `budget.includes_company_hours` は、予算が社内工数の金額化まで含むか。`false` なら現金の額と比べ、`true` なら金額化した総額と比べる。既存の予算枠がなく、この資料で申請額を決める場合は `budget` を省略し、現金の額を申請額として示す。
- `alternatives` は他の採用手段。`official` か `quote` で金額が入っているものだけ比較可能として返る。

実行は標準入力から渡すのを既定にする。社内の予算や原価をファイルに残さないためである。ファイルに書いた場合は `python3 scripts/summarize_trial_cost.py input.json` で読み、終わったら消す。

```bash
python3 scripts/summarize_trial_cost.py <<'JSON'
{"trial": {"kind": "paid_work"}, "candidate_pay": {"basis": "hourly", "hourly_rate": 2000, "hours": 12, "expenses": 0}}
JSON
```

出力の `candidate_pay` は候補者への支払いの幅、`company_hours` は役割ごとの工数と金額化の可否、`other_costs` は出所別の周辺費用、`totals` は現金の額と社内工数込みの額と予算との差、`alternatives` は比較可能かどうか、`flags` は資料に書く前に確定させる点である。`totals.cash_is_complete` が `false` のとき、現金の総額を確定額として書かない。
